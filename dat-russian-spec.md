# DAT-RU: Русская версия Divergent Association Task

## Спецификация проекта

---

## Что это и зачем

**Оригинал:** [datcreativity.com](https://www.datcreativity.com) — тест дивергентного мышления из Гарварда/McGill. Пользователь вводит 10 существительных, максимально далёких друг от друга по смыслу. Алгоритм считает среднее семантическое расстояние между ними. Чем выше — тем более «дивергентно» ты думаешь.

**Наша задача:** Сделать то же самое на русском языке. Открытое, бесплатное веб-приложение.

**Результат:** Сайт, на который можно дать ссылку из Facebook-поста. Человек заходит, вводит 10 русских слов, получает балл и сравнение с ИИ.

---

## Как работает оригинал (логика подсчёта)

1. Пользователь вводит 10 слов (существительные, нарицательные, единственное число)
2. Система берёт первые 7 валидных слов
3. Считает косинусное расстояние между каждой парой (всего 21 пара из 7 слов)
4. Берёт среднее этих 21 расстояний
5. Умножает на 100 → это и есть балл (DAT score)
6. Шкала: 0–200, среднее ~78, рекорд ~107

**Косинусное расстояние** = 1 − cos(θ), где θ — угол между двумя векторами слов в модели эмбеддингов. Близкие по смыслу слова → маленькое расстояние. Далёкие → большое.

---

## Архитектура: два варианта

### Вариант A: Предрассчитанная матрица (рекомендуемый)

**Идея:** Заранее берём словарь из 30 000 русских существительных, считаем все эмбеддинги, сохраняем в компактный файл. Фронтенд загружает его и считает расстояния прямо в браузере.

**Плюсы:**
- Нет сервера → нет расходов на хостинг
- Работает мгновенно
- Можно разместить на GitHub Pages / Vercel / Netlify бесплатно
- Не зависит от внешних API

**Минусы:**
- Файл с эмбеддингами весит ~50–150 МБ (можно сжать до ~20–40 МБ)
- Словарь фиксированный — слова вне словаря не принимаются

**Это рекомендуемый вариант. Ниже описан именно он.**

### Вариант B: Серверный

**Идея:** Фронт шлёт слова на бэкенд (Python/FastAPI), бэкенд считает расстояния через полную модель.

**Плюсы:**
- Полная модель, любое слово
- Маленький фронтенд

**Минусы:**
- Нужен сервер (VPS ~$5–10/мес)
- Зависимость от аптайма
- Модель в памяти ~2–4 ГБ

Используем pymorphy2 для фильтрации:

```python
import pymorphy2

morph = pymorphy2.MorphAnalyzer()

def is_valid_noun(word):
    """Проверяет: существительное, нарицательное, не аббревиатура"""
    word = word.lower().strip()
    parses = morph.parse(word)
    for p in parses:
        if 'NOUN' in p.tag and 'Name' not in p.tag and 'Surn' not in p.tag:
            # Привести к именительному падежу, ед. числу
            normal = p.normal_form
            return normal
    return None
```

#### 1.3. Отфильтровать и экспортировать

```python
import numpy as np
import json

# Собрать все слова, которые:
# 1) Есть в модели navec
# 2) Являются существительными по pymorphy2
# 3) Достаточно частотные (топ-30К)

valid_words = {}
for word in navec.vocab.words[:50000]:  # топ-50К по частоте
    normal = is_valid_noun(word)
    if normal and normal in navec and normal not in valid_words:
        valid_words[normal] = navec[normal]

# Должно получиться ~15,000–30,000 слов

# Вариант 1: Экспорт как JSON с квантизированными векторами
# Сжимаем 300 float32 → 300 int8 (потеря точности минимальна для косинуса)
export = {}
for word, vec in valid_words.items():
    # Нормализуем вектор (для косинусного расстояния)
    norm = vec / np.linalg.norm(vec)
    # Квантизируем в int8 (-128..127)
    quantized = np.clip(norm * 127, -128, 127).astype(np.int8)
    export[word] = quantized.tolist()

with open('vectors.json', 'w') as f:
    json.dump(export, f)

# Вариант 2 (компактнее): бинарный формат
# Отдельный файл со словарём + отдельный файл с матрицей
words = sorted(valid_words.keys())
matrix = np.array([valid_words[w] / np.linalg.norm(valid_words[w]) 
                    for w in words])
matrix_q = np.clip(matrix * 127, -128, 127).astype(np.int8)

# Сохранить
with open('words.json', 'w') as f:
    json.dump(words, f, ensure_ascii=False)
np.save('matrix.npy', matrix_q)  # ~9 МБ для 30K × 300

print(f"Словарь: {len(words)} слов")
print(f"Размер матрицы: {matrix_q.nbytes / 1024 / 1024:.1f} МБ")
```

**Ожидаемый размер:** ~9 МБ (матрица) + ~0.5 МБ (список слов) = ~10 МБ до сжатия, ~5–7 МБ с gzip.

#### 2.2. Основная логика (JavaScript)

```javascript
// Загрузка данных
let WORDS = [];      // массив строк
let MATRIX = null;   // Int8Array, shape [N, 300]
const DIM = 300;

async function loadData() {
    const [wordsResp, matrixResp] = await Promise.all([
        fetch('data/words.json'),
        fetch('data/matrix.bin')
    ]);
    WORDS = await wordsResp.json();
    const buffer = await matrixResp.arrayBuffer();
    MATRIX = new Int8Array(buffer);
}

// Поиск слова в словаре (с нормализацией через предрассчитанные формы)
function findWord(input) {
    const word = input.toLowerCase().trim();
    const idx = WORDS.indexOf(word);
    if (idx === -1) return null;
    return idx;
}

// Получить вектор по индексу
function getVector(idx) {
    return MATRIX.slice(idx * DIM, (idx + 1) * DIM);
}

// Косинусное расстояние между двумя int8-векторами
function cosineDistance(a, b) {
    let dot = 0, normA = 0, normB = 0;
    for (let i = 0; i < DIM; i++) {
        dot += a[i] * b[i];
        normA += a[i] * a[i];
        normB += b[i] * b[i];
    }
    const similarity = dot / (Math.sqrt(normA) * Math.sqrt(normB));
    return 1 - similarity;  // расстояние: 0 = идентичны, 2 = противоположны
}

// Подсчёт DAT score
function calculateDAT(wordIndices) {
    // Берём первые 7 валидных
    const indices = wordIndices.slice(0, 7);
    if (indices.length < 7) return null;
    
    const vectors = indices.map(i => getVector(i));
    
    // Все пары (21 штука)
    let totalDistance = 0;
    let pairCount = 0;
    for (let i = 0; i < vectors.length; i++) {
        for (let j = i + 1; j < vectors.length; j++) {
            totalDistance += cosineDistance(vectors[i], vectors[j]);
            pairCount++;
        }
    }
    
    return (totalDistance / pairCount) * 100;
}
```

#### 2.3. Валидация ввода

```javascript
function validateWord(input) {
    const word = input.toLowerCase().trim();
    
    // Проверки:
    if (!word) return { valid: false, error: 'Пустое поле' };
    if (word.includes(' ')) return { valid: false, error: 'Только одно слово' };
    if (/[a-zA-Z]/.test(word)) return { valid: false, error: 'Только русские слова' };
    
    const idx = findWord(word);
    if (idx === null) return { valid: false, error: 'Слово не найдено в словаре' };
    
    return { valid: true, index: idx, normalized: WORDS[idx] };
}
```

### Шаг 3: Нормализация слов (важная деталь)

Пользователь может ввести слово в любой форме: «кошки», «столом», «деревьев». Нужно приводить к нормальной форме (лемме).

**Решение:** Предрассчитать маппинг словоформ → лемма.

```python
# В скрипте подготовки данных:
import pymorphy2
morph = pymorphy2.MorphAnalyzer()

# Для каждого слова из словаря генерируем все словоформы
form_to_lemma = {}
for word in valid_words:
    parses = morph.parse(word)
    for p in parses:
        if 'NOUN' in p.tag:
            for form in p.lexeme:
                form_to_lemma[form.word] = word

# Сохранить (это будет ~2–5 МБ в JSON)
with open('forms.json', 'w') as f:
    json.dump(form_to_lemma, f, ensure_ascii=False)
```

Тогда во фронтенде:
```javascript
// Загрузить forms.json
let FORMS = {};

function normalizeWord(input) {
    const word = input.toLowerCase().trim().replace('ё', 'е');
    // Сначала ищем как лемму
    if (WORDS.includes(word)) return word;
    // Потом как словоформу
    if (FORMS[word]) return FORMS[word];
    return null;
}
```

## Технические нюансы и подводные камни

### 1. Размер файлов
Главная проблема — `forms.json` (маппинг словоформ) может быть большим. Решения:
- Использовать gzip-сжатие (все современные хостинги поддерживают)
- Или: загружать формы лениво, по мере ввода (через Service Worker)
- Или: делать нормализацию на стороне простого серверлесс-эндпоинта (Vercel Function)

### 2. Квантизация
Переход float32 → int8 вносит погрешность ~2–5% в косинусное расстояние. Для наших целей это приемлемо. Если хочется точнее — использовать int16 (размер файла ×2).

### 3. Буква «ё»
Всегда заменять «ё» на «е» при поиске (многие пишут без точек).

### 4. Уменьшительные и разговорные формы
«Кошечка», «домик», «человечек» — pymorphy2 может не привести к базовой форме. Нужно решить: принимать как есть или требовать базовую форму. Рекомендация: принимать, если слово есть в модели.

### 5. Многозначность
Слово «ключ» — это и ключ от двери, и родник, и музыкальный ключ. Модель эмбеддингов даёт один усреднённый вектор. Это нормально — оригинальный DAT работает так же.

### 6. Невалидированность
Важный дисклеймер на сайте: «Это неофициальная русская адаптация. Баллы приблизительные и не сопоставимы напрямую с оригинальным английским тестом. Для научных целей используйте оригинал.»

### 7. Мобильная версия
80%+ трафика из Facebook — мобильный. Фронтенд должен быть mobile-first. 10 полей ввода на маленьком экране — нужен хороший UX (возможно, показывать по одному полю, как шаги).
